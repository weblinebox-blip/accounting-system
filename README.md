# سامانه حسابداری — اسکلت پروژه + ماژول فاکتور خرید

این پروژه شامل اسکلت کامل بک‌اند و فرانت‌اند سیستم حسابداری است. ماژول **فاکتور خرید** به‌طور کامل پیاده‌سازی شده (فرم دستی، ایمپورت اکسل، لیست با جستجو/فیلتر/مرتب‌سازی، ویرایش، حذف، خروجی Excel/PDF). ماژول‌های فروش، هزینه‌ها، برگشتی و گزارش‌ها در فاز بعدی تکمیل می‌شوند؛ جداول دیتابیس آن‌ها از قبل در اسکیما آماده است.

## پیش‌نیازها
- Node.js نسخه ۱۸ به بالا
- PostgreSQL نسخه ۱۴ به بالا

## راه‌اندازی بک‌اند

```bash
cd backend
npm install
cp .env.example .env
# مقدار DATABASE_URL در .env را با اطلاعات دیتابیس خودتان جایگزین کنید

# ساخت جداول دیتابیس
npm run migrate

# اجرای سرور (حالت توسعه)
npm run dev
```

سرور روی `http://localhost:4000` بالا می‌آید.

## راه‌اندازی فرانت‌اند

```bash
cd frontend
npm install
npm run dev
```

فرانت روی `http://localhost:5173` بالا می‌آید و درخواست‌های `/api` به‌صورت خودکار به بک‌اند (پورت ۴۰۰۰) هدایت می‌شوند.

## فرمت فایل اکسل ایمپورت فاکتور خرید

فایل اکسل باید شامل این ستون‌ها باشد (نام ستون‌ها می‌تواند فارسی یا انگلیسی باشد):

| کد محصول | تعداد | قیمت خرید یوان | قیمت خرید تومان |
|---|---|---|---|

ستون‌های «جمع قیمت یوان» و «جمع قیمت تومان» نیازی به وارد کردن ندارند — سرور خودش محاسبه می‌کند.

## نکات مهم برای توسعه بعدی

- **دیتابیس**: تمام جداول لازم برای فروش، هزینه‌ها و برگشتی از قبل در `docs/database-schema.sql` تعریف شده‌اند.
- **موجودی کالا**: هر عملیات خرید/فروش/برگشت به‌صورت خودکار جدول `inventory_movements` و `products.current_stock` را به‌روز می‌کند — این پایه‌ی گزارش «موجودی کالا» و «کالاهای پرفروش» است.
- **شماره‌گذاری فاکتور**: منطق تولید شماره در `backend/src/services/invoiceNumberService.js` است و برای فروش/هزینه/برگشتی هم قابل استفاده مجدد است.
- **تاریخ شمسی**: تاریخ‌ها در دیتابیس میلادی ذخیره می‌شوند؛ تبدیل شمسی فقط در فرانت‌اند (`utils/jalaliDate.js`) انجام می‌شود.
- **آماده برای دیپلوی**: بک‌اند و فرانت‌اند کاملاً مجزا هستند و می‌توانید بک‌اند را روی یک سرور Node (مثلاً با PM2) و فرانت را به‌صورت استاتیک (`npm run build`) روی هاست/CDN اجرا کنید.
